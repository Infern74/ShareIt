# ShareIt — сервис совместного использования вещей

**Современный микросервисный backend для шеринга вещей между пользователями.**  
Платформа позволяет арендовать любые предметы — от инструментов до электроники, с системой бронирования, отзывами и поиском.

---

## 🎯 Функциональные возможности

### 🔧 Основные модули:
* **Главный сервис (`server`):** Управление пользователями, вещами, запросами и отзывами
* **Сервис бронирований (`gateway`):** Обработка аренды, проверка доступности, календарь
* **Микросервисная архитектура:** Четкое разделение ответственности между компонентами

### 📋 Ключевые функции:
* **Бронирование вещей:** Почасовая аренда с подтверждением владельцем
* **Система запросов:** Пользователи могут создать запрос на отсутствующую вещь
* **Поиск с фильтрацией:** По названию, описанию, доступности
* **Отзывы и рейтинги:** Оценка после завершения бронирования
* **Валидация:** Комплексная проверка дат, статусов, прав доступа

## 🏗️ Архитектура
```
ShareIt/
├── gateway/ # Сервис бронирований (API Gateway)
│ ├── Dockerfile
│ └── src/
├── server/ # Основной сервис (вещи, пользователи, запросы)
│ ├── Dockerfile
│ └── src/
└── docker-compose.yml # Оркестрация всех сервисов и БД
```

**Особенности архитектуры:**
- **API Gateway паттерн:** Единая точка входа для клиентов
- **Разделение бизнес-логики:** Бронирования отделены от каталога вещей
- **Готовность к масштабированию:** Каждый сервис можно масштабировать независимо

## 🛠 Технологический стек

* **Backend:** Java 11, Spring Boot 2.7.14
* **Базы данных:** PostgreSQL (основная), H2 (для тестирования)
* **ORM:** Spring Data JPA, Hibernate
* **Валидация:** Hibernate Validator, кастомные аннотации
* **Тестирование:** JUnit 5, Mockito, Spring Boot Test
* **Контейнеризация:** Docker, Docker Compose
* **Сборка:** Maven 3.6+
* **Документация API:** Spring Doc OpenAPI 3.0
* **Утилиты:** Lombok, MapStruct

## 🗄️ Модель данных

### Основные сущности:
1. **User** — регистрация и профили пользователей
2. **Item** — вещи для аренды с описанием и статусом доступности
3. **Booking** — бронирования с датами, статусами (WAITING, APPROVED, REJECTED)
4. **ItemRequest** — запросы пользователей на отсутствующие вещи
5. **Comment** — отзывы к завершенным бронированиям

### Ключевые связи:
- Пользователь → Вещи (один ко многим)
- Вещь → Бронирования (один ко многим)
- Бронирование → Отзыв (один к одному)

## 🚀 Быстрый старт

### Вариант 1: Запуск через Docker Compose (рекомендуется)
```bash
# Клонируйте репозиторий
git clone https://github.com/Infern74/Shareit.git
cd Shareit

# Запустите все сервисы и базы данных
docker-compose up -d
```
### Вариант 2: Локальный запуск
```bash
# Сборка проекта
mvn clean package

# Запуск основного сервиса
java -jar server/target/server-0.0.1-SNAPSHOT.jar

# Запуск gateway (в отдельном терминале)
java -jar gateway/target/gateway-0.0.1-SNAPSHOT.jar
```
### Портфолио сервисов после запуска:
* Gateway (API Gateway): http://localhost:8080

* Основной сервис: http://localhost:9090

* База данных PostgreSQL: localhost:5432

* Документация Swagger: http://localhost:8080/swagger-ui.html

## 🔌 Основные API Endpoints
### Пользователи (/users)
* POST /users — регистрация нового пользователя

* GET /users/{id} — получение информации о пользователе

* PATCH /users/{id} — обновление данных

### Вещи (/items)
* POST /items — добавление новой вещи

* GET /items/{id} — получение информации о вещи

* PATCH /items/{id} — обновление данных вещи

* GET /items/search?text={query} — поиск вещей

### Бронирования (/bookings)
* POST /bookings — создание бронирования

* PATCH /bookings/{id}?approved={true/false} — подтверждение/отклонение

* GET /bookings/{id} — получение информации о бронировании

* GET /bookings/owner — бронирования владельца

* GET /bookings/booker — бронирования арендатора

### Запросы (/requests)
* POST /requests — создание запроса на вещь

* GET /requests/{id} — получение запроса

* GET /requests/all — все запросы пользователя

## 🔧 Ключевые технические решения
### 1. Паттерн API Gateway
* Централизованная аутентификация и маршрутизация

* Упрощение клиентских интеграций

* Возможность добавления rate limiting и кэширования

### 2. Сложная бизнес-логика бронирования
* Валидация пересечения дат

* Проверка прав доступа (только владелец может подтвердить бронь)

* Автоматическое обновление статусов по времени

### 3. Оптимизация запросов к БД
* Пагинация для списков

* Индексы на часто используемых полях

* Batch-операции для массовых обновлений

## 📈 Производительность и масштабируемость
